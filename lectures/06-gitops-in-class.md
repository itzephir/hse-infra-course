Можно делать изменения в кластере через тот же gitlab ci: pipeline, push изменений

А если хочется декларативно обеспечить 1в1 соответствие схеме? - модель pull и argocd
Есть много проблем с применением спеки%
1. Pipeline применил конфигурацию и завершился
2. Ручные изменения расходятся с git - можно регламентировать ручные изменения
3. Нужен постоянный контроль управляемого состояния
4. Правила исправления определяет команда - можно например только через git

В чем проблема делать через gitlab ci - gitlab runner теперь имеет полный доступ к конфигурации, то есть каждый может создать флоу и что угодно сделать на кластере

В pull модели доступ только у системы доставки

На семинаре сделали типо git, поменяли configmap, но важно помимо sync, сделать restart deployment
